# Конфигурация

[English](Config.md) | Русский

Каждая настройка — переменная окружения с префиксом `OUTBOX_`. Значения также читаются из файла `.env`, если он есть;
окружение имеет приоритет.

Всё читается и проверяется на старте. Некорректная длительность или порог вне допустимого диапазона останавливают
процесс, причём выводятся **все** проблемы сразу — так на диагностику неверно настроенного развёртывания уходит один
перезапуск, а не по одному на каждую ошибку.

## Приложение

| Переменная                    | По умолчанию | Смысл                                                                                              |
|-------------------------------|--------------|----------------------------------------------------------------------------------------------------|
| `OUTBOX_APP_NAME`             | `outbox`     | Передаётся в PostgreSQL как `application_name` — именно под ним сервис виден в `pg_stat_activity`. |
| `OUTBOX_APP_ENV`              | `prod`       | Метка окружения.                                                                                   |
| `OUTBOX_APP_INSTANCE`         | hostname     | Записывается в колонку `owner` захваченной строки, чтобы было видно, какая реплика держит lease.   |
| `OUTBOX_APP_SHUTDOWN_TIMEOUT` | `30s`        | Ограничивает всю процедуру остановки.                                                              |

## Стримы и драйверы

**Стрим** — логическое направление, которое продюсер указывает в строке. **Драйвер** — подключение к конкретному
брокеру. Несколько стримов могут делить один драйвер.

```dotenv
OUTBOX_STREAMS=local,global

OUTBOX_STREAM_LOCAL_DRIVER=rmq
OUTBOX_STREAM_GLOBAL_DRIVER=kfk

OUTBOX_DRIVER_RMQ_TYPE=rabbitmq
OUTBOX_DRIVER_RMQ_DSN=amqp://user:pass@rabbit:5672/

OUTBOX_DRIVER_KFK_TYPE=kafka
OUTBOX_DRIVER_KFK_BROKERS=kafka-1:9092,kafka-2:9092
```

Настройки драйвера ищутся по точному совпадению ключа из закрытого набора.
Опечатка в ключе — ошибка на старте, а не настройка, которая молча ничего не
делает. И драйвер, чьё имя является префиксом другого (`rmq` и `rmq_local`),
читает только свои переменные.

### Несколько брокеров одного типа

Драйвер не привязан к *типу* брокера — драйвер это одно соединение, и их может
быть столько, сколько брокеров нужно достать. Четыре стрима на трёх отдельных
инстансах RabbitMQ — это четыре блока драйверов, у каждого свой DSN:

```dotenv
OUTBOX_STREAMS=local,test,global,tetra

OUTBOX_STREAM_LOCAL_DRIVER=rmq_local
OUTBOX_DRIVER_RMQ_LOCAL_TYPE=rabbitmq
OUTBOX_DRIVER_RMQ_LOCAL_DSN=amqp://user:pass@rabbit-a:5672/
OUTBOX_DRIVER_RMQ_LOCAL_PREFIX=loc

# …и так далее для rmq_test, rmq_global и rmq_tetra.
```

Два драйвера могут смотреть в один брокер и остаются независимыми: у каждого своё
соединение, свой пул каналов и своё именование. Имена драйверов, различающиеся
только `-` против `_`, отвергаются на старте — оба адресуют один и тот же блок
`OUTBOX_DRIVER_…`.

Разобранный пример со всеми подводными камнями — в
[сценарии 5](UseCases.ru.md#5-четыре-стрима-на-трёх-инстансах-rabbitmq).

### Общее для всех драйверов

| Ключ          | По умолчанию                | Смысл                                                                       |
|---------------|-----------------------------|-----------------------------------------------------------------------------|
| `TYPE`        | —                           | `rabbitmq` (либо `rmq`, `amqp`) или `kafka`. Обязателен.                    |
| `PREFIX`      | —                           | Добавляется к каждому имени топика — чтобы делить брокер между окружениями. |
| `PREFIX_SEP`  | `_` для AMQP, `.` для Kafka | Разделитель между префиксом и топиком.                                      |
| `VERSION_SEP` | `_` для AMQP, `.` для Kafka | Разделитель перед суффиксом `vN`.                                           |

Эффективное имя, на которое должен подписаться потребитель:

```
[prefix + prefix_sep] + topic + [version_sep + "v" + version]
```

то есть при `PREFIX=prod`, топике `user.created` и `target.version = 2`
получится `prod_user.created_v2` в AMQP.

### RabbitMQ

| Ключ              | По умолчанию | Смысл                                                                                                                                                   |
|-------------------|--------------|---------------------------------------------------------------------------------------------------------------------------------------------------------|

| `MANDATORY`       | `true`       | Просить брокер вернуть недоставляемое сообщение, а не отбросить его. Так ошибка маршрутизации становится видимым permanent-отказом вместо тихой потери. |
| `PUBLISH_TIMEOUT` | `15s`        | Ограничивает одну публикацию вместе с ожиданием подтверждения.                                                                                          |

## Отправка

| Переменная                           | По умолчанию | Смысл                                                                                                                                                                          |
|--------------------------------------|--------------|--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `OUTBOX_DISPATCH_BATCH_SIZE`         | `200`        | Сообщений за один захват. Батч, который стабильно приходит полным, означает backlog — это и показывает `outbox_batch_size`.                                                    |
| `OUTBOX_DISPATCH_WORKERS`            | `8`          | Параллелизм публикации на стрим.                                                                                                                                               |
| `OUTBOX_DISPATCH_POLL_INTERVAL`      | `5s`         | Как часто искать работу, когда пайплайн никто не будит. При включённых уведомлениях это сверка, а не основной путь.                                                            |
| `OUTBOX_DISPATCH_LEASE_TTL`          | `2m`         | Срок жизни захвата. Должен превышать `PUBLISH_TIMEOUT`; если lease истечёт в процессе, батч перезахватят и опубликуют повторно — это и считает `outbox_lease_conflicts_total`. |
| `OUTBOX_DISPATCH_MAX_ATTEMPTS`       | `5`          | Всего попыток публикации до перевода в `failed`.                                                                                                                               |
| `OUTBOX_DISPATCH_BACKOFF_BASE`       | `1m`         | Первая задержка повтора. Удваивается с каждой попыткой.                                                                                                                        |
| `OUTBOX_DISPATCH_BACKOFF_MAX`        | `1h`         | Потолок. Без него удвоение минуты переваливает за сутки к одиннадцатой попытке.                                                                                                |
| `OUTBOX_DISPATCH_BACKOFF_JITTER`     | `0.2`        | Доля разброса задержки. Без него всё, что упало во время недоступности брокера, становится доступным в один и тот же момент после его возвращения.                             |
| `OUTBOX_DISPATCH_PUBLISH_TIMEOUT`    | `15s`        | Ограничивает одну публикацию.                                                                                                                                                  |
| `OUTBOX_DISPATCH_WRITE_BACK_TIMEOUT` | `30s`        | Ограничивает запись результата. Намеренно щедрый: потеря этой записи означает повторную публикацию батча.                                                                      |
| `OUTBOX_DISPATCH_NOTIFY_ENABLED`     | `true`       | Просыпаться на INSERT через `LISTEN`/`NOTIFY`. Выключите там, где роль БД не может создавать триггеры, — всё продолжит работать на polling'е.                                  |
| `OUTBOX_DISPATCH_NOTIFY_CHANNEL`     | `outbox_new` | Должен совпадать с каналом, с которым создан триггер.                                                                                                                          |
| `OUTBOX_DISPATCH_NOTIFY_DEBOUNCE`    | `50ms`       | Окно, в котором пачка INSERT'ов схлопывается в одно пробуждение.                                                                                                               |
| `OUTBOX_DISPATCH_NOTIFY_JITTER`      | `100ms`      | Разброс между репликами, чтобы один INSERT не заставлял их всех делать захват в одну и ту же миллисекунду.                                                                     |

## Служебные задачи

Каждый цикл берёт advisory lock в PostgreSQL, поэтому выполняется на одной реплике за цикл — сколько бы их ни было
развёрнуто.

| Переменная                          | По умолчанию | Смысл                                                                                                                 |
|-------------------------------------|--------------|-----------------------------------------------------------------------------------------------------------------------|
| `OUTBOX_JANITOR_ENABLED`            | `true`       |                                                                                                                       |
| `OUTBOX_JANITOR_RECLAIM_INTERVAL`   | `30s`        | Как часто истёкшие lease возвращаются в очередь.                                                                      |
| `OUTBOX_JANITOR_STATS_INTERVAL`     | `30s`        | Обновление gauge-метрик. Намеренно реже poll-цикла: счётчики берутся по частичным индексам, но это всё равно запросы. |
| `OUTBOX_JANITOR_RETENTION`          | `168h`       | Сколько хранится доставленная строка. `0` отключает очистку — и тогда таблица растёт неограниченно.                   |
| `OUTBOX_JANITOR_RETENTION_INTERVAL` | `5m`         |                                                                                                                       |
| `OUTBOX_JANITOR_RETENTION_BATCH`    | `5000`       | Строк за один DELETE, чтобы транзакция оставалась короткой.                                                           |
| `OUTBOX_JANITOR_LOCK_KEY`           | `809021150`  | Пространство имён advisory lock'а.                                                                                    |

## Пересылка в dead-letter

Когда сообщение перестаёт переотправляться, его можно переслать туда, где его ждёт потребитель. Строка в таблице
остаётся в любом случае: dead-letter-топик — это сигнал, а не сама запись.

| Переменная           | По умолчанию         | Смысл                                            |
|----------------------|----------------------|--------------------------------------------------|
| `OUTBOX_DLQ_ENABLED` | `false`              |                                                  |
| `OUTBOX_DLQ_STREAM`  | —                    | Должен быть одним из сконфигурированных стримов. |
| `OUTBOX_DLQ_TOPIC`   | `outbox.dead-letter` |                                                  |

Пересланное сообщение сохраняет payload и получает заголовки
`x-outbox-original-topic`, `x-outbox-original-stream`, `x-outbox-attempts` и
`x-outbox-permanent`.
