# Сценарии использования

[English](UseCases.md) | Русский

Девять развёртываний — от ноутбука до кластера. Каждое достаточно полное, чтобы
скопировать, и каждое заканчивается ошибками, к которым эта среда располагает, —
это та часть, которую стоит прочитать дважды.

Через все шесть проходит одно правило: **сообщение пишется в той же транзакции,
что и бизнес-изменение**. Всё остальное — обвязка.

| | Рецепт | Для кого |
|---|---|---|
| 1 | [Laravel, PostgreSQL 18 и RabbitMQ под Docker Compose](usecases/1-laravel-docker.ru.md) | PHP-приложение на ноутбуке или одном хосте |
| 2 | [Один VDS, supervisord](usecases/2-vds-supervisord.ru.md) | Одна машина, диспетчер как процесс под супервизором |
| 3 | [Kubernetes, Kafka, автомасштабирование по возрасту бэклога](usecases/3-kubernetes-kafka.ru.md) | Кластер, где число реплик следует за бэклогом |
| 4 | [Bare metal, systemd, несколько инстансов на одном хосте](usecases/4-systemd-baremetal.ru.md) | Несколько диспетчеров на одной машине |
| 5 | [Четыре стрима на трёх инстансах RabbitMQ](usecases/5-multi-rabbitmq.ru.md) | Один продюсер, пишущий в несколько брокеров |
| 6 | [Go-продюсер на database/sql](usecases/6-database-sql.ru.md) | Сервис на `sqlx`, `gorm` или стандартной библиотеке |
| 7 | [Модульный монолит: инбокс вместо брокера](usecases/7-inbox-monolith.ru.md) | Ограниченные контексты в одной базе, брокера нет вовсе |
| 8 | [Два сервиса, две базы, брокера нет](usecases/8-inbox-two-services.ru.md) | Доставка в инбокс другого сервиса |
| 9 | [Мёртвые письма в таблицу, а не в топик](usecases/9-dlq-table.ru.md) | Разбор упавшего через SQL |

Раньше это был один документ. Он вырос до размера, при котором его никто не
читал целиком, поэтому теперь каждый рецепт — отдельная страница, а это
указатель.
